已定稿的 4 项决策

2026-09-28 确认
1SOOP 不要"大厅"，本期只做手粘添加。 「大厅」tab 保持 PandaLive 专属，顶栏搜索也只对 PandaLive 有效；SOOP 主播通过第 ② 屏的地址粘贴添加。搜索/发现另开一期（bililive-go 无发现类接口，需另找 SOOP 检索端点并实测风控）。
2取流走 TS 移植，不引入 bililive-go 子进程。 把 player_live_api.php（type=live / type=aid）、broad_stream_assign.html 调度、HLS preloading 过滤代理这几段逻辑用 TS 在主进程重写，与 PandaLive 完全同构。
所以本稿不需要"来源=bililive-go"之类的暴露，第 ③ 屏的画法即为最终形态。移植时的对位关系：fetchPageMeta → fetchChannelInfo → fetchAid → fetchViewURL → appendQuery，以及 resolvePageBroadNo 的离线三态（页面 nBroadNo=null / 落到 /channel/null = 明确下播，不回退；仅页面缺字段才回退用路径 bno）。
3SOOP 保留"账密自动重登"，第 ④ 屏该区块照做。 与 PandaLive（已移除账密直登）行为不一致是有意为之：SOOP 的 Cookie 失效面更宽（19+ / 限区 / 匿名降级），无人值守录制必须能自愈。凭据沿用现有加密存储，日志与导出脱敏。
4数据模型主键改为 platform + userId 复合键。 现在 Anchor（src/shared/types.ts:10）只以 userId 为键、全模型无 platform 字段，判重（ipc.ts:114）、isFollowing、录制任务查找全是单键，必须一并改造 + 迁移历史数据。房间地址与请求头也不能再硬编码 PandaLive：目前散在 AnchorCard.vue:58、MonitorView.vue:207、tgFormat.ts:18 三处，要收敛成 roomUrl(platform, id) + parseRoomInput()。SOOP 的"userId"是频道名（如 demo_kr04），卡片右上位显示它没问题。

实现顺序

① 类型与主键改造（shared/types.ts + store 判重 + 历史数据迁移）→ ② LiveCard 平台徽标 + MonitorView 平台筛选行 + 地址收敛（roomUrl / parseRoomInput）→ ③ SOOP 取流 TS 移植（含 HLS 过滤代理）→ ④ SOOP 登录窗 / Cookie 分域 + 账密自动重登 → ⑤ 录制目录 Videos/<平台>/<主播>/ 与视频库平台维度 → ⑥ 监控轮询与通知接入 SOOP（复用 watcher，注意别把 PandaLive 的限速队列串台）。
